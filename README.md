## 1.7.0：全仓借币卡片 MMR 旁显示上涨空间

在有持仓、带「全」标记的 FS 卡片「实时 MMR」右侧，自动显示一个整数百分比小框，无需输入账户数据。仅支持原生 BINANCE Portfolio Margin / BITGET UTA 借币卖现货腿；逐仓、普通现货、FF、SF、GC 和零持仓不显示。

百分比表示**从当前价格还能上涨多少到达粗估风险线**，不是已经发生爆仓的概率。四舍五入为整数；按显示值 ≤100% 标红，>100% 标绿。数据缺失、失败、无交点显示灰色「—」，不保留旧百分比。悬停或点击可查看口径和读取时间。无需打开插件弹窗，设置页不再放账户列表或手填入口。

每个可见看板页面每 30 秒共用一次账户读取，只在有适用卡片时请求，后台标签页暂停。复用已配置站点的现有只读客户端：`/api/config` 与 `/api/ex-position?ex=binance|bitget`。只读取持仓、MMR、显示保证金、余额和当前价格；不读取或导出交易所密钥，不持久保存账户快照，不调用交易端点，不新增权限。同标签页并发合并，不同标签页账户不共享。

目前适配已核实的 `index-CW16nN3e.js` / `cD` 与 `index-UbpzoVda.js` / `cE` 客户端导出，软件升级后若结构改变则停止显示数字，不能自动猜测接口。

这是前端近似模型，并非交易所确认的强平价格：

- 显示合约保证金近似统一账户调整后权益，MMR × 保证金近似总维保。
- 全仓 FS 卖出现货数量近似借款，暂停但未平仓的卡片仍参与账户汇总；逐仓及普通现货不算借款。按当前价计负债，不再次除以两倍杠杆。
- 同账户实际合约多空及同币正现货余额计入净敞口，其他交易所盈利不抵扣。
- 维保按各币借款和合约市值分摊，随被测试币价格变化。币安参考 E/M=1.05，Bitget 参考 M/E=100% 首个风险线。
- 单币上涨，其余币及 BTC 抵押品价格固定，USDT 按稳定币；不支持用此模型测试 BTC/USDT 自身。未核实完整负债、抵押折扣及动态档位会造成偏差，绿色仅代表该假设下空间较大。
- 过期、重复卡片身份、异常仓位、缺失行情不能显示数字；读取时间并不代表各行情字段的交易所更新时间。

## 安装和部署

本仓库就是可直接加载的扩展目录，无需构建、打包或服务器。部署到 Chrome：

1. 克隆或下载本仓库。
2. 打开 `chrome://extensions`，开启“开发者模式”。
3. 点击“加载已解压的扩展程序”，选择**包含 `manifest.json` 的仓库根目录**。
4. 点击扩展图标，在“套利看板地址”填入自己的站点 URL，例如 `https://dashboard.example.com`；“Radar 站点地址”默认是 `https://47.79.37.237`，也可以改成自己的域名。点击“保存并启用”，允许扩展访问所填的看板站点。
5. 打开或刷新看板，检查卡片标题右边是否出现“雷达 ↗”。点击链接核对 Radar 页面中的标的、模式和交易所。

两个地址都可以输入完整页面 URL；扩展会提取协议、域名和端口。看板地址只决定脚本在哪个站点运行。Radar 地址只用于生成链接，路径固定为 `/radar/`。修改 Radar 地址并保存后，已打开的看板链接也会更新。扩展不会主动请求 Radar；只有点击链接时，浏览器才会打开相应 URL。

更新源码后，在 `chrome://extensions` 点击本扩展卡片上的**重新加载**按钮，再刷新看板。如果修改了看板地址，重新打开扩展弹窗保存新地址并允许该站点访问。其他人安装时只需重复以上步骤，不需要修改代码里的域名。

## 链接规则

- 卡片的两个交易所标签按页面顺序写入 `combo`。
- 金色标签代表合约 `F`，绿色标签代表现货 `S`，组合得到 `FF`、`FS` 或 `SF`。
- 标的使用卡片上显示的名称；标题开头的装饰性 emoji 会移除。
- 例如标的 `Q`、两侧合约交易所 `aster` 与 `binance`：`https://47.79.37.237/radar/?tab=FF&mode=FF&q=Q&combo=FF.Q.aster.binance`。

卡片缺少标的、交易所或可识别的类型时，扩展不会猜测参数，也不会添加可能错误的链接。

## 给维护 agent 的说明

- 文件入口：`manifest.json` 定义权限与弹窗；`background.js` 注册站点脚本；`popup.js` 保存两个站点地址；`content.js` 处理卡片与动态更新；`linking.js` 解析卡片并构造 URL。
- 本项目没有依赖或构建步骤。修改 JavaScript 后运行 `node --test test/*.test.js`，再到 Chrome 扩展页重新加载并刷新看板实测。
- 发布新版本时先修改 `manifest.json` 的 `version`，提交并推送仓库。用户仍需在自己的 Chrome 中重新加载扩展；GitHub 更新不会自动替换已加载的本地文件。

## 1.4.0：限制解除时声音与卡片提醒

- 同一页面先查到「限制」、之后获得新的有效「可开」结果时，播放当前看板页面 `audio#myAudio` 的现有报警声音，对应卡片短暂抖动并高亮8秒，同时显示解除提示。仅提示HL公共持仓限制解除，不下单。
- 同币种持续可开不重复报警；首次查询就是可开不报警。再次受限后恢复可再次提醒。接口错误、过期、同批缓存和乱序旧结果不触发解除提醒；错误后仍需获得新的有效可开结果。
- 多个卡片/同一批币种的提醒合并播放一次，最长8秒。克隆页面音频元素来播放，不暂停或拖动原页面自身的报警。尊重页面音频元素的静音/音量。
- 设置新增「限制解除提醒（声音 + 抖动）」开关，默认开启；与自动查询开关独立，手动查询也能触发。关闭提醒立即停止本插件的声音与高亮。
- 后台标签页仍暂停自动查询和提醒；回到前台按配置重新查询。浏览器阻止声音时保留解除提示并显示「播放提醒」按钮。未找到页面报警音时明确提示，不擅自换成其他音效。
- 为减少晃动系统开启减弱动画时不抖动，保留高亮；页面刷新后重新建立受限基线。

更新为1.4.0时需包含新增 alerts.js，重新加载Chrome扩展后刷新看板。新增提醒不增加权限或查询频率。

## 1.5.1：隐藏无有效结果的状态

查询失败、接口异常或未识别币种时，不再显示「未知」标签，同时移除之前的状态，不保留旧「可」。保留「查」按钮供重试；后台仍将该结果视为无效，不触发解除提醒。有效结果「限 / 可」、查询中和已过期结果的待查提示不变。
